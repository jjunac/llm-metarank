# AGENTS.md

Astro static site plus a TypeScript data pipeline. `README.md` is the reference for scoring,
coverage rules, source cohorts, and cost methodology; read it before changing ranking logic or
adding a source.

## Commands

- `npm run check` — the full gate, in order: `astro check` + `tsc --noEmit`, Vitest, dataset
  validation, static build. Run before finishing.
- Focused checks: `npx vitest run scripts/costs.test.ts`, `npx vitest run -t "test name"`,
  `npm run typecheck`, `npm run data:check`.
- There is no CI, lint, or formatter config; `npm run check` is the only automated gate.
  Node >= 22.23.4 is required.
- Vitest runs in Node (no jsdom). React component tests use `renderToStaticMarkup` from
  `react-dom/server`.

## Data pipeline

- `data/leaderboard.json` is generated by `scripts/build-dataset.ts`; never hand-edit it. After
  changing snapshots, `data/sources.json`, `data/models.json`, or pipeline logic, run
  `npm run data:build` then `npm run data:check` before running tests.
- Build input is `data/snapshots/<sourceId>/latest.json`. Dated files beside it are retrieval
  snapshots, not benchmark release dates; result dates live in `sourceUpdatedAt` and
  `benchmarkRelease`.
- Rows whose `rawName` does not match the registry are silently excluded from scores. Run
  `npm run data:review` (it prints `raw -> normalized`) and add aliases in `data/models.json`.
  Matching only indexes canonical `name` + `aliases`; the `patterns` field in `scripts/types.ts`
  is declared but not implemented.
- A source id is simultaneously the `sources.json` id, snapshot directory name, and `--only`
  value. Adding a source requires a `data/sources.json` entry, fetch/parse code under
  `scripts/fetch`/`scripts/parse`, and registration in `FETCHERS` in `scripts/refresh.ts`.
  `sources.json` maps each category to the `RawEntry.metrics` key (`overall` is the primary score).
- `npm run data:refresh` refuses a dirty tree, downloads the selected sources, rebuilds, then
  commits and pushes `data/` itself. For local work use
  `npm run data:refresh -- --fetch-only` (writes snapshots only) or `-- --only=<sourceId>`, then
  run `npm run data:build`.
- Blocked or failed fetches intentionally keep the last good `latest.json`, mark the source stale,
  and make refresh exit nonzero; without `--fetch-only`, successful sources are still rebuilt and
  committed. Do not erase warnings or fabricate data. LMArena Text and Code Arena need full Chromium
  (`npx playwright install chromium`); the legacy headless shell is blocked by Cloudflare.

## Architecture and conventions

- Static two-page site: `src/pages/index.astro` and `src/pages/methodology.astro`. Only
  `Leaderboard` is hydrated (`client:idle`); everything else is pre-rendered.
- `src/lib/data.ts` deliberately strips build-only fields before sending data to the island
  (`costedRuns`, `metricCosts`, source `date`/`runId`, non-overall metrics, `dominatedBy`). If
  hydrated UI needs one of them, update `toClientDataset` and `src/lib/data.test.ts` too.
- Ranking thresholds live in `scripts/build-dataset.ts`: overall requires 5 sources including at
  least one general and one coding source; categories require 2. Cost frontiers are built in
  `scripts/costs.ts`; `data:check` recomputes them and requires each cost to stay paired with the
  exact scored run. Keep `README.md` and `src/pages/methodology.astro` in sync with formula changes.
- Path aliases: `@/*` -> `src/*`, `@data/*` -> `data/*`. Scripts import local TypeScript modules
  with `.js` specifiers (for example `./types.js`); keep that convention.
